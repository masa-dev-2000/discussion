# 0003. バックグラウンド実行マネージャ(多重実行・上限・ガード)

- Status: Accepted
- Date: 2026-06

## Context

当初は実行ループが論壇画面(Arena)に紐づいており、画面を離れると実行が「迷子」になっていた。
複数議論の同時進行、画面遷移をまたいだ継続、リソース不足時の保護が必要になった。

## Decision

実行ループを画面から切り離し、アプリ全体の **実行マネージャ(`RunsProvider` / `useRuns`)** に集約する。

- 議論 ID ごとにバックグラウンドで実行。画面を離れても継続し、戻ると進捗が見える。
- **同時実行数の上限**(`settings.maxConcurrent`、既定 2)。満杯時は開始不可。
- **接続健全性チェック**。Ollama に接続できない時は開始不可(リソースガード)。
- トークン更新は `requestAnimationFrame` で間引く。
- 議論データ(発言・要約・状態)は App の state を単一の真実とし、マネージャは patch で更新→永続化に乗る。

## Consequences

- 「A を走らせつつ B を開始」が可能。一覧/論壇に「実行中 N / M」を表示。
- ローカル GPU が1枚なら Ollama 側で生成は順番待ちになる(アプリの上限は“同時に走らせる本数”の制御であり、真の並列性能は別)。
- 接続先をマネージャが監視するため、実行中に全体の接続先を切り替えると進行中の議論に影響しうる(現状は許容)。
